# 04. 역할별 업무와 일정

> 6주 = **개발 4주 + 폴리싱·QA 2주**
> 4주차 말에 [필수 규칙서](01_rules_essential.md)가 전부 동작해야 한다. 확장 기능은 5주차에만 넣는다.

---

## 1. 마일스톤

| 주차 | 목표 | 완료 기준 (데모로 확인) |
|---|---|---|
| **1주차** | 기반 구축 | 두 명이 접속해서 서로 머리와 손이 보인다. 회색 박스 방에 앉아 있다 |
| **2주차** | 핵심 루프 (회색 박스) | 퀴즈 → 정답 → 총 지급 → 구속 → 사격 → 결과가 두 화면에서 똑같이 진행된다 |
| **3주차** | 규칙 완성 + 에셋 1차 교체 | 필수 규칙(피해, 공포 단계, 자신·진행자 쏘기, 동시 판정)이 전부 동작한다. 주요 모델과 사운드가 들어간다 |
| **4주차** | 콘텐츠 통합 + 필수 버전 완성 | 처음부터 끝까지 끊김 없이 한 판이 된다. 진행자 대사와 문제가 전부 들어간다. **외부인 플레이테스트 1회** |
| **5주차** | 폴리싱 + 확장 기능 | 확장 상위 2~3개(E5, E1 등). 연출 디테일. **주말에 기능 동결** |
| **6주차** | QA + 발표 준비 | 버그 수정만 한다. 발표 빌드, 백업 빌드, 시연 영상 |

> **매주 금요일 통합 데모**: 전원이 헤드셋을 쓰고 main 빌드로 한 판 해본다. 문서에 적힌 완료 기준을 통과하지 못하면 다음 주 첫 작업으로 넘긴다.

## 2. 역할별 업무

### 메인 개발 (팀장)

**책임:** 게임 로직 전체, 통합, 메인 씬, 빌드. 최종 결정권.

| 주차 | 업무 |
|---|---|
| 1 | XRI·OpenXR 설치 및 설정, 폴더 구조, `GameStateMachine` 뼈대, `TuningConfig` ScriptableObject, 회색 박스 방 (테이블·의자·버튼 4개·부스) |
| 2 | 퀴즈 시스템 (출제·타이머·오답 잠금·판정), `Revolver` 로직 + 단위 테스트, 총 잡기·방아쇠, 구속(Interactor 비활성화) |
| 3 | 히트박스와 `DamageModel` (머리·몸통), 사수 턴 4가지 행동, 공포 단계 컨트롤러, 상태 이벤트 → 사운드·연출 연결 지점 제공 |
| 4 | 전체 통합, 에셋 교체, 콘텐츠(CSV) 연동, 버그 수정, 플레이테스트 진행 |
| 5 | 확장 기능 구현 (E5 협동/배신 우선), 연출 디테일 |
| 6 | 버그 수정, 최적화, 발표 빌드 |

**공통:** main 병합 전 코드 리뷰, 매일 짧은 진행 공유, 문서 최신화.

### 멀티플레이 담당

**책임:** 연결, 동기화, 네트워크 공정성, 보이스챗.

| 주차 | 업무 |
|---|---|
| 1 | NGO 설치, LAN 호스트/접속 UI(간단한 버튼), 플레이어를 좌석 2개에 배정, 머리·손 위치 동기화, Multiplayer Play Mode 환경 구성 |
| 2 | 상태 머신 동기화(`NetworkVariable`), 입력 요청 RPC(버튼·방아쇠), 총 소유권 이전, **Vivox 보이스챗 연결** |
| 3 | 먼저 누르기 판정(네트워크 시간 비교, 동시 판정), 사격 결과 동기화, 구속·피해 상태 동기화, 연결 끊김 처리(상대 이탈 시 승리 처리) |
| 4 | 실제 헤드셋 2대로 지연 테스트, 동기화 버그 수정, 보이스챗 음량·에코 조정 |
| 5 | 확장 기능 네트워크 처리(팔 절단·유리 내구도 동기화), Relay 연결(출시 대비, 선택) |
| 6 | 발표 현장 네트워크 리허설, 연결 실패 대비책 |

**주의:** 게임 로직(`Core/`)에 네트워크 코드를 섞지 않는다. 네트워크 계층은 `Net/` 폴더에서 로직을 감싸기만 한다.

### 모델링 담당

**책임:** 모든 3D 에셋. VR 성능 예산 준수.

| 주차 | 업무 |
|---|---|
| 1 | 아트 방향 레퍼런스 보드(조명·색감·진행자 컨셉 3안) → 팀 합의. 규격 확정(스케일·피벗) |
| 2 | **리볼버** (실린더 회전, 공이치기, 약실 6칸이 보이는 구조, 애니메이션용 분리 파트), 퀴즈 버튼 패널, 테이블과 구속 의자 |
| 3 | 방 환경, 방탄유리 부스, **진행자 1차**(실루엣이 모호한 외형), 플레이어 아바타(머리·손·몸통) |
| 4 | 구속구 애니메이션(전기의자 클램프), 진행자 기본 애니메이션(대기·바라보기·분노·박수), 피해 표현(피 데칼) |
| 5 | 확장: 유리 금 단계 3종, 절단된 팔 모델, 진행자 추가 애니메이션 |
| 6 | 최적화(폴리곤·머티리얼 수), 시각 버그 수정 |

**성능 가이드 (PC VR 기준 초기값):** 장면 전체 50만 트라이앵글 이하, 머티리얼 최소화(아틀라스 사용), 텍스처 2K 이하. 1주차에 메인 개발과 함께 측정해서 확정한다.

### 사운드 담당

**책임:** 효과음, 진행자 목소리, 배경음, 공간 음향 설정.

| 주차 | 업무 |
|---|---|
| 1 | 사운드 레퍼런스(벅샷 룰렛 등 분석), 진행자 목소리 변조 방향 2~3안 시연 → 팀 합의, Unity Audio Mixer 그룹 구성(대사·효과음·BGM·보이스챗) |
| 2 | 핵심 효과음: 공이치기, 실린더 회전, 공포탄(딸깍), 발사, 구속구(전기 소리), 버튼, 타이머 째깍 |
| 3 | 진행자 대사 녹음 + 변조 (콘텐츠 담당의 대본 기준), 심장박동·숨소리(중상), 유리에 총알이 튕기는 소리 |
| 4 | **공포 단계별 BGM 레이어 4단계**, 공간 음향 조정(진행자 목소리 위치), 상태 이벤트에 사운드 연결 |
| 5 | 확장: 유리 금 가는 소리, 절단·출혈, 진행자 속삭임(뒤에서 들리는 공간 음향) |
| 6 | 볼륨 밸런스, 헤드셋으로 최종 점검 |

**팁:** 공포는 소리가 반이다. **완전한 정적**도 효과음이다. 방아쇠를 당기기 직전에 모든 소리를 끊는 연출을 시도해보자.

### 콘텐츠 담당

**책임:** 문제 은행, 진행자 대본, 수치 밸런스, 플레이테스트·QA 주관.

| 주차 | 업무 |
|---|---|
| 1 | **종이 프로토타입**(주사위 + 문제 카드)으로 팀원과 규칙 검증 → 수치 표 초안 수정. CSV 양식 확정 (아래) |
| 2 | 문제 60개 (난이도 하·중·상 각 20), **진행자 대본 1차** (필수 대사 이벤트 전부, 이벤트당 3~5줄) → 사운드 담당에게 전달 |
| 3 | 문제 100개 이상으로 확충, 대본 수정, 플레이테스트 체크리스트 작성 |
| 4 | **외부인 플레이테스트 진행 및 기록** (어디서 긴장했나, 어디서 지루했나), 수치 조정 제안 |
| 5 | 확장: 기억 질문 템플릿(E6), 협동/배신 관련 대사, 엔딩 대본 |
| 6 | **QA 주관**: 테스트 케이스 순회, 버그 목록 관리, 발표 대본 작성 |

**문제 CSV 양식:**

```
id,difficulty,category,question,choice1,choice2,choice3,choice4,answer
q001,1,상식,"사람의 뼈는 몇 개인가?",106,206,306,406,2
```

- `difficulty`: 1(하) 2(중) 3(상), `answer`: 정답 번호(1~4)
- VR 화면에서 읽어야 하므로 **문제는 30자 안팎, 선택지는 10자 이내**로 쓴다.

**진행자 대사 양식:**

```
event,id,text,emotion
quiz_start,qs01,"자, 머리를 써볼 시간이다.",calm
shot_self_reward,ssr01,"하...! 미쳤군. 마음에 들어.",delighted
```

## 3. 의존 관계 (마감 약속)

다른 사람의 작업을 막는 항목이다. **마감을 꼭 지킨다.**

| 무엇을 | 누가 → 누구에게 | 언제까지 |
|---|---|---|
| 모델 규격(스케일·피벗) | 모델링 ↔ 메인 개발 | 1주차 수 |
| 상태 머신 이벤트 목록 | 메인 개발 → 사운드·멀티 | 1주차 금 |
| 진행자 대본 1차 | 콘텐츠 → 사운드 | 2주차 수 |
| 리볼버 모델 | 모델링 → 메인 개발 | 2주차 금 |
| 문제 CSV 60개 | 콘텐츠 → 메인 개발 | 2주차 금 |
| 진행자 녹음 1차 | 사운드 → 메인 개발 | 3주차 금 |
| 진행자 모델 + 기본 애니메이션 | 모델링 → 메인 개발 | 4주차 수 |

## 4. 협업 규칙

- **매일:** 메신저에 3줄 공유 (어제 한 것 / 오늘 할 것 / 막힌 것). 막힌 것은 숨기지 말고 바로 말한다.
- **매주 금:** 통합 데모 + 다음 주 계획.
- **작업 관리:** GitHub Issues에 업무를 올리고 담당자를 지정한다. 이 문서의 표를 이슈로 옮기면 된다.
- **Git:** 1주차에 전원 `git lfs install`, UnityYAMLMerge 설정을 한다. 메인 씬은 메인 개발만 수정한다. 자세한 내용은 [기술 검토 5절](03_tech_review.md#5-협업-기술-규칙).
- **결정 기록:** 규칙이나 수치가 바뀌면 해당 문서를 수정하고, 커밋 메시지에 이유를 적는다.

## 5. QA 체크리스트 (6주차, 콘텐츠 담당 주관)

- [ ] 처음부터 끝까지 10판을 연속으로 진행해도 멈추지 않는다
- [ ] 호스트와 클라이언트 양쪽이 각각 이기는 경우가 정상 동작한다
- [ ] 동시 판정, 시간 초과, 오답 잠금이 정상 동작한다
- [ ] 사수 턴의 행동 4가지 결과가 전부 정상이다 (실탄/공포탄 각각)
- [ ] 공포 단계 0~3의 연출이 전부 나온다
- [ ] 한 명이 접속을 끊으면 남은 쪽이 정상적으로 승리 처리된다
- [ ] 72fps 이상을 유지한다 (가장 무거운 공포 단계 3 기준)
- [ ] 처음 해보는 사람이 설명 없이 3분 안에 규칙을 이해한다
- [ ] 보이스챗이 양방향으로 들리고 에코가 없다
