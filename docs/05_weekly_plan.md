# 05. 주차별 플랜

> 매주 **목표 → 인원별 할 일 → 주고받을 것 → 금요일 데모 통과 기준** 순서로 정리했다.
> 체크박스는 그대로 GitHub Issues로 옮겨 쓸 수 있다. 끝낸 항목은 이 문서에서도 체크한다.
> 역할별 책임과 협업 규칙은 [04_roles_and_schedule.md](04_roles_and_schedule.md)를 본다.

| 주차 | 단계 | 한 줄 목표 |
|---|---|---|
| 1주차 | 개발 | 둘이 접속해서 회색 박스 방에 마주 앉는다 |
| 2주차 | 개발 | 핵심 루프가 회색 박스로 한 바퀴 돈다 |
| 3주차 | 개발 | 필수 규칙이 전부 동작하고 에셋이 들어오기 시작한다 |
| 4주차 | 개발 | 필수 버전 완성, 외부인 플레이테스트 |
| 5주차 | 폴리싱 | 확장 기능 2~3개 + 연출 디테일, **주말에 기능 동결** |
| 6주차 | QA | 버그 수정과 발표 준비만 한다 |

## 1주차: 기반 구축

**목표:** 두 명이 접속해서 회색 박스 방에 마주 앉고, 서로의 머리와 손이 보인다.

### 메인 개발
- [ ] XR Interaction Toolkit, OpenXR 설치 및 헤드셋 연결 확인
- [ ] 타깃 기기 결정 (PC VR / Quest 단독) → 팀 공유
- [ ] 폴더 구조 생성 (`Assets/_Project/...`, [기술 검토 3절](03_tech_review.md#3-아키텍처) 참고)
- [ ] 회색 박스 방: 테이블, 의자 2개, 버튼 4개 × 2세트, 진행자 부스(투명 박스)
- [ ] `GameStateMachine` 뼈대 (상태 enum + 전이 함수, 네트워크 없이)
- [ ] `TuningConfig` ScriptableObject (필수 규칙서 9절의 수치 전부)
- [ ] **상태 이벤트 목록** 작성 → 사운드·멀티 담당에게 공유 (금)
- [ ] 팀 전원 Git LFS, UnityYAMLMerge 설정 확인

### 멀티플레이
- [x] Netcode for GameObjects 설치 (VR Multiplayer 템플릿에 포함)
- [x] VR Multiplayer 템플릿으로 프로젝트 생성
- [ ] 템플릿 코드 검토 → 그대로 쓸 부분과 바꿀 부분 정리 (아바타 동기화, Vivox 연동, 로비 UI)
- [ ] LAN 호스트/접속 버튼 UI (임시)
- [ ] 접속 순서대로 좌석 1·2에 배정, 서로 마주보게 스폰
- [ ] 머리·양손 위치 동기화
- [ ] Multiplayer Play Mode + XR Device Simulator로 에디터에서 2인 테스트 환경 구성 → 팀에 사용법 공유

### 모델링
- [ ] 아트 레퍼런스 보드 (조명, 색감, 방 분위기)
- [ ] 진행자 컨셉 3안 (악마인지 사람인지 모호한 실루엣) → 팀 투표
- [ ] 모델 규격 확정 (1unit=1m, Y-up, 피벗 위치) → 메인 개발과 합의 (수)
- [ ] VR 성능 예산 확정 (메인 개발과 빈 씬에서 측정)
- [ ] 리볼버 블록아웃 (실린더·공이치기·방아쇠 파트 분리 구조)

### 사운드
- [ ] 레퍼런스 분석 (벅샷 룰렛 등: 정적, 저음, 효과음 타이밍)
- [ ] 진행자 목소리 변조 2~3안 시연 → 팀 투표
- [ ] Audio Mixer 그룹 구성 (대사 / 효과음 / BGM / 보이스챗)
- [ ] 효과음 목록 작성 (필수 / 확장 구분)

### 콘텐츠
- [ ] **종이 프로토타입** 제작 (주사위 = 리볼버, 문제 카드 = 퀴즈)
- [ ] 팀원과 최소 5판 플레이 → 결과 기록 (한 판 길이, 자신 쏘기 선택 빈도, 지루한 구간)
- [ ] 수치 표 수정안 제출 ([필수 규칙서 9절](01_rules_essential.md#9-수치-표-튜닝용-초기값))
- [ ] 문제 CSV·대사 CSV 양식 확정 (메인 개발과 합의)
- [ ] 문제 20개 (테스트용)

### 주고받을 것
| 무엇을 | 누가 → 누구에게 | 마감 |

| 모델 규격 | 모델링 ↔ 메인 개발 | 수 |
| 상태 이벤트 목록 | 메인 개발 → 사운드·멀티 | 금 |
| 테스트용 문제 20개 | 콘텐츠 → 메인 개발 | 금 |

### 금요일 데모 통과 기준
- [ ] 헤드셋 2대로 접속해서 서로 마주 앉아 있다
- [ ] 상대가 고개를 돌리고 손을 흔드는 게 보인다

## 2주차: 핵심 루프 (회색 박스)

**목표:** 퀴즈 → 정답 → 총 지급 → 구속 → 사격 → 결과가 두 화면에서 똑같이 진행된다.

### 메인 개발
- [ ] 퀴즈 시스템: CSV 불러오기, 출제, 타이머, 버튼 입력
- [ ] 오답 잠금, 시간 초과 처리
- [ ] `Revolver` 로직 (6칸 약실, 진행, 실탄 여부, 재장전) + **단위 테스트**
- [ ] 총 잡기(XRI Grab), 방아쇠 입력, 떨어뜨리면 2초 뒤 테이블로 복귀
- [ ] 대상 구속: 손 Interactor 비활성화, 손 위치를 팔걸이에 고정
- [ ] 사격 판정: 레이캐스트 → 플레이어에 맞았는지만 (부위는 3주차)

### 멀티플레이
- [ ] 상태 머신 동기화 (`NetworkVariable<GameState>`)
- [ ] 입력 요청 RPC: 버튼 누름, 방아쇠 당김(조준 방향 포함)
- [ ] 호스트에서만 판정과 무작위 처리, 약실 상태는 클라이언트에 보내지 않기
- [ ] 총 소유권 이전 (사수만 잡을 수 있음)
- [ ] **Vivox 보이스챗 연결**

### 모델링
- [ ] 리볼버 완성 (실린더 회전, 공이치기, 약실 6칸이 보이는 구조) → 메인 개발 전달 (금)
- [ ] 퀴즈 버튼 패널 (누르면 들어가는 구조)
- [ ] 테이블, 구속 의자 (구속구는 별도 파트)

### 사운드
- [ ] 핵심 효과음: 공이치기, 실린더 회전, 공포탄(딸깍), 발사
- [ ] 구속구(전기 소리), 버튼 클릭, 타이머 째깍
- [ ] 효과음을 상태 이벤트에 연결하는 컴포넌트 (메인 개발과 협의)

### 콘텐츠
- [ ] 문제 60개 (난이도 하·중·상 각 20) → 메인 개발 전달 (금)
- [ ] **진행자 대본 1차**: 필수 대사 이벤트 전부, 이벤트당 3~5줄 → 사운드 전달 (수)
- [ ] 진행자 캐릭터 설정 문서 (말투, 금지 표현, 성격 키워드)

### 주고받을 것
| 무엇을 | 누가 → 누구에게 | 마감 |
|---|---|---|
| 진행자 대본 1차 | 콘텐츠 → 사운드 | 수 |
| 리볼버 모델 | 모델링 → 메인 개발 | 금 |
| 문제 CSV 60개 | 콘텐츠 → 메인 개발 | 금 |

### 금요일 데모 통과 기준
- [ ] 문제가 나오고, 먼저 맞힌 사람이 총을 잡을 수 있다
- [ ] 상대가 구속되고, 쏘면 실탄/공포탄 결과가 양쪽 화면에서 같다
- [ ] 보이스챗으로 대화가 된다

## 3주차: 필수 규칙 완성 + 에셋 1차 교체

**목표:** [필수 규칙서](01_rules_essential.md)의 모든 규칙이 동작한다.

### 메인 개발
- [ ] 히트박스 (머리·몸통·양팔) + `DamageModel` (머리 즉사, 몸통 중상 → 2회 사망, 팔은 몸통 처리)
- [ ] 사수 턴 4가지 행동: 실린더 돌리기, 상대 쏘기, 자신 쏘기(15% 보상), 진행자 쏘기
- [ ] 자신 쏘기 보상: 다음 퀴즈 오답 1개 제거
- [ ] 공포 단계 컨트롤러 (조명, 제한시간, 난이도, BGM 전환)
- [ ] 중상 효과: 비네팅 (URP Volume)
- [ ] 공이치기 지연 0.6초
- [ ] 리볼버·버튼·의자 모델 교체

### 멀티플레이
- [ ] 먼저 누르기 판정: 네트워크 시간 비교, 0.15초 이내 동시 판정
- [ ] 사격 결과, 피해 상태, 공포 단계 동기화
- [ ] 머리 위치 전송 빈도 조정 (피하기 판정용)
- [ ] 연결 끊김 처리 (상대 이탈 시 남은 쪽 승리)

### 모델링
- [ ] 방 환경 (벽, 바닥, 조명 기구)
- [ ] 방탄유리 부스
- [ ] **진행자 1차 모델**
- [ ] 플레이어 아바타 (머리·손·몸통)

### 사운드
- [ ] **진행자 대사 녹음 + 변조** → 메인 개발 전달 (금)
- [ ] 심장박동, 숨소리 (중상 상태)
- [ ] 방탄유리에 총알이 튕기는 소리

### 콘텐츠
- [ ] 문제 100개 이상으로 확충
- [ ] 대본 수정 (녹음 테스트 결과 반영)
- [ ] 플레이테스트 체크리스트 + 관찰 기록 양식 작성
- [ ] 4주차 외부 테스터 섭외 (3~5명)

### 주고받을 것
| 무엇을 | 누가 → 누구에게 | 마감 |
|---|---|---|
| 진행자 녹음 1차 | 사운드 → 메인 개발 | 금 |
| 문제 100개 | 콘텐츠 → 메인 개발 | 금 |
| 진행자·아바타 모델 | 모델링 → 메인 개발 | 금 |

### 금요일 데모 통과 기준
- [ ] 머리 명중 시 즉사, 몸통 2회 명중 시 사망
- [ ] 사수 턴 4가지 행동이 전부 동작한다
- [ ] 아무도 못 맞추면 공포 단계가 오르고 조명·시간이 바뀐다
- [ ] 동시 판정 연출이 나온다

## 4주차: 통합 + 필수 버전 완성

**목표:** 처음부터 끝까지 끊김 없이 한 판이 된다. 외부인이 해본다.

### 메인 개발
- [ ] 진행자 대사 시스템 (이벤트별 대사 풀, 연속 중복 방지)
- [ ] 인트로·엔딩(승리/사망) 흐름
- [ ] 진행자 모델·애니메이션 연결
- [ ] 전체 통합, 버그 수정
- [ ] 프로파일링 (72fps 이상 확인)
- [ ] 플레이테스트용 빌드 (수)

### 멀티플레이
- [ ] 헤드셋 2대로 지연 테스트 (일부러 와이파이 환경에서도 테스트)
- [ ] 동기화 버그 수정
- [ ] 보이스챗 음량·에코 조정

### 모델링
- [ ] 구속구 애니메이션 (전기의자 클램프)
- [ ] 진행자 기본 애니메이션: 대기, 바라보기, 분노, 박수 → 메인 개발 전달 (수)
- [ ] 피 데칼

### 사운드
- [ ] 공포 단계별 BGM 레이어 4단계
- [ ] 공간 음향 조정 (진행자 목소리가 부스에서 들리게)
- [ ] "방아쇠 직전 정적" 연출 시도

### 콘텐츠
- [ ] **외부인 플레이테스트 진행** (목~금)
- [ ] 관찰 기록: 어디서 긴장했나, 어디서 지루했나, 규칙을 이해 못한 곳
- [ ] 수치 조정 제안서 → 팀 회의

### 주고받을 것
| 무엇을 | 누가 → 누구에게 | 마감 |
|---|---|---|
| 진행자 애니메이션 | 모델링 → 메인 개발 | 수 |
| 플레이테스트 빌드 | 메인 개발 → 콘텐츠 | 수 |
| 플레이테스트 결과 | 콘텐츠 → 전원 | 금 |

### 금요일 데모 통과 기준
- [ ] **필수 버전 완성**: 한 판을 처음부터 끝까지 멈춤 없이 진행
- [ ] 외부 테스터가 설명 없이 3분 안에 규칙을 이해
- [ ] 금요일 회의에서 5주차에 넣을 확장 기능 2~3개 확정

## 5주차: 폴리싱 + 확장 기능

**목표:** 차별점을 만든다. 주말에 **기능 동결**.

> 아래는 추천 조합(E5 협동/배신 + E1 팔 절단 + E6 기억 질문) 기준이다. 4주차 회의 결과에 따라 바꾼다.

### 메인 개발
- [ ] **E5 진행자 사살·협동/배신**: 유리 내구도, 공동 생존 엔딩, 배신 보상(확정 권총)
- [ ] **E1 팔 절단**: 컨트롤러 비활성화, 양팔 절단 시 머리로 버튼 누르기
- [ ] 플레이테스트 피드백 반영
- [ ] 연출 디테일 (진행자 반응 타이밍, 구속 연출)

### 멀티플레이
- [ ] 유리 내구도, 팔 절단 상태 동기화
- [ ] 엔딩 분기 동기화
- [ ] (선택) Relay 연결 테스트

### 모델링
- [ ] 유리 금 단계 3종 (금 → 거미줄 → 파괴)
- [ ] 절단된 팔 모델
- [ ] 진행자 추가 애니메이션 (쓰러짐, 박수)

### 사운드
- [ ] 유리 금 가는 소리, 유리 깨지는 소리
- [ ] 절단·출혈 소리
- [ ] 엔딩 음악·효과음

### 콘텐츠
- [ ] **E6 기억 질문** 템플릿 ("몇 번 쐈지?" 등)과 정답 생성 규칙 → 메인 개발
- [ ] 협동/배신 관련 대사, 엔딩 대본 → 사운드 (화)
- [ ] QA 테스트 케이스 작성 ([04 문서 5절](04_roles_and_schedule.md#5-qa-체크리스트-6주차-콘텐츠-담당-주관) 기반)

### 금요일 데모 통과 기준
- [ ] 확장 기능이 필수 기능을 망가뜨리지 않는다
- [ ] **기능 동결 선언**: 이후 새 기능은 받지 않는다

## 6주차: QA + 발표 준비

**목표:** 버그 수정과 발표 준비만 한다. 새 기능은 없다.

### 메인 개발
- [ ] 버그 수정 (콘텐츠 담당의 버그 목록 우선순위 순)
- [ ] 최적화
- [ ] 발표 빌드 + 백업 빌드 (수)
